In short

Distill a 2D foundation model into a 4D point encoder, one point at a time

Self-supervised pretraining for 4D point clouds has mostly used intra-modal pretexts, and the few methods that borrow from 2D foundation models distill one global embedding per clip, throwing away the per-patch features those models compute. Cross4D-JEPA renders each frame from geometry alone, maps every visible 3D point to the teacher patch it projects to, and trains the student to predict those features densely, in latent space, with no masking, negatives, or decoder.

Controlled studies attribute the gain to the granularity of the correspondence rather than to the teacher: image and video teachers tie, and an untrained teacher recovers most of the gain.

Method

Correspondence from geometry, targets computed once

  1. RenderEach frame of the point clip is rendered to a depth-shaded image from a single virtual camera. No RGB or calibration is needed, so the same pipeline runs on depth-only and mesh datasets.
  2. Back-projectA frozen teacher (DINOv2 by default) encodes the render. A z-buffer maps every visible point to the patch it lands in, giving a per-point target; occluded points are masked.
  3. Distill denselyThe Point4D student turns the geometry-only clip into spatio-temporal tokens, and a linear head predicts each token's target from its nearest point under a cosine loss.

The teacher runs once per clip before training; its targets are cached and the teacher is freed, so pretraining costs one GPU for about 35 minutes on MSR-Action3D.

Results

What drives the gain

Frozen-encoder linear-probe top-1 unless noted; mean ± standard deviation over seeds. Hover any mark for its value, or open the table under each chart.

Dense supervision wins on every dataset

With the same teacher, student and budget, predicting per-point targets beats predicting one global target per clip by 0.18 to 0.29, several times either error bar.

Table 1. MSR-Action3D uses DINOv2 (5 dense / 8 global seeds); DeformingThings4D and NTU RGB+D 60 use V-JEPA 2 (5 seeds each).

Image and video teachers tie

Swapping DINOv2 for DINOv3, V-JEPA 2 or VideoMAE V2 moves dense results by at most 0.023, while the dense–global gap stays between 0.21 and 0.29 for every teacher.

Table 2, MSR-Action3D, 5 seeds per teacher (8 for DINOv2 global).

Most of the gain needs no learned semantics

Same render, correspondence, 9 × 9 grid and objective; only the teacher's training changes. Raw rendered pixels already reach 0.685, and an untrained ViT 0.776. The same ordering holds for zero-shot HOI4D segmentation: 13.95 mIoU from raw pixels, 15.81 from the untrained ViT, 16.61 from DINOv2, against a 4.6 floor.

Table 3, MSR-Action3D, 3 seeds.

Dense needs about four tokens per frame

Holding Point4D's parameters at 3.28M, dense supervision stays flat down to 4 tokens per frame and degrades below that; global never overtakes it. On the official P4Transformer, dense also beats global (0.617 vs. 0.376), and shrinking the ball-query radius from 0.7 to 0.1 leaves dense between 0.58 and 0.68.

Table 4, MSR-Action3D, 3 seeds per point (more for n2 = 64).

Ahead of intra-modal pretexts on the same student

Re-implemented on Point4D with the same data and probe, at their best budget from a 12× sweep, masked and latent intra-modal pretexts reach 44.7 to 65.8%; dense distillation reaches 82.9%. Fine-tuned, it reaches 92.0%, close to published methods that use 3–13× larger backbones.

Table 6, MSR-Action3D. Published rows use their own backbones and are not directly comparable.

Fewer labels, larger gain

Fine-tuning from the dense encoder beats training the same architecture from scratch at every label fraction, by 0.17 with 10% of labels and still by 0.10 with all of them.

MSR-Action3D end-to-end fine-tuning, 3 seeds.

pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -e ".[preprocess,dev]"
